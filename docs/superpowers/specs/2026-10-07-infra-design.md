# eGrađanin korak po korak — infrastructure design

Date: 2026-10-07
Status: approved in conversation, pending written review

## Purpose

A free, public, step-by-step guide that takes a non-technical or elderly
person from nothing to a working eUprava account and a consent ID. Built
for a community hackathon. The product content (flow, copy, screenshots)
is written by other team members. This document covers only the
infrastructure: repo layout, content schema, build, wizard runtime,
deploy, and quality gates.

## Constraints

- Infrastructure cost must be zero. No backend, no database, no accounts,
  no paid services. The whole product is a static site.
- Hosted on GitHub Pages from this public repo, at the default github.io
  address. A custom domain may be added later and must be a one-line change.
- Phones are the only target device: mixed Android and iPhone, including
  older models and browsers. Mobile-first, no desktop-specific work.
- Accessibility is a must, not polish. Large text, high contrast, works at
  200% zoom, no hover-only UI, every page readable without JavaScript.
- Content is Serbian. Authored in Cyrillic (ћирилица), which is the
  default. Latin (латиница) is generated by transliteration at build time.
- All technical identifiers are English: node ids, route prefixes, file and
  folder names, config keys, code. Only user-facing text is Serbian.
- Content for v1 is frozen. The team hands over Markdown and images; there
  is no CMS and no editing UI. Staleness of eUprava screenshots is out of
  scope for this iteration.

## Product shape

The guide is a branching wizard, technically a state machine stored as a
graph. Nodes are screens. Edges are answers. The user starts at a start
node and follows edges until reaching an end node.

The process is long and interrupted: users open eUprava in another tab,
and physically visit a post office to get the consent ID activated. The
infrastructure therefore supports resuming where the user left off, steps
that hand off to an external site or place, and full-screen "cards" the
user can show to a clerk or print.

## Repo layout

```
content/
  graph.yaml                 # the state machine: nodes and edges
  ui-strings.yaml            # fixed interface labels, Cyrillic
  translit-overrides.yaml    # word-level Cyrillic->Latin overrides, empty by default
  nodes/
    <node-id>/
      index.md               # Cyrillic body (optional for question and end nodes)
      *.png / *.jpg          # screenshots referenced by relative path
src/                         # Astro site: layouts, pages, components, lib
  lib/graph.ts               # schema, loading, validation
  lib/translit.ts            # Cyrillic->Latin transliteration
  lib/progress.ts            # local-storage progress (client script)
public/                      # manifest, icons, robots
docs/superpowers/specs/      # this document and future specs
.github/workflows/           # build, check, deploy
```

One folder per node, named by the node id. Node ids are English,
lowercase, hyphenated, and are the URL slugs. Images sit next to the
Markdown and are referenced by relative path, so a node folder is a
self-contained unit.

## Graph schema

`content/graph.yaml`:

```yaml
start: have-id-card

nodes:
  have-id-card:
    type: question
    title: Да ли имате личну карту са чипом?
    group: Припрема
    answers:
      - label: Да
        next: have-email
      - label: Не
        next: how-to-get-id-card

  why-egradjanin:
    type: step
    title: Шта добијате као еГрађанин
    next: have-id-card # single next renders one "Даље" button

  register-euprava:
    type: step
    title: Направите налог на еУправи
    group: Регистрација
    external:
      label: Отворите еУправу
      url: https://euprava.gov.rs/
    answers:
      - label: Урадио/ла сам
        next: verify-account
      - label: Нисам успео/ла
        next: help-registration

  post-office-card:
    type: card
    title: Покажите ово на шалтеру поште
    group: Пошта
    next: done

  done:
    type: end
    title: Честитамо, имате налог и ID за сагласност
```

Node types:

| type     | body     | outgoing edges                               | extras              |
| -------- | -------- | -------------------------------------------- | ------------------- |
| question | optional | `answers`, two or more (no upper limit)      | —                   |
| step     | required | either one `next` or `answers` (one or more) | optional `external` |
| card     | required | one `next`                                   | print layout        |
| end      | optional | none                                         | —                   |

Rules enforced at build time; any violation fails the build:

- Every `next` points to an existing node id.
- Every node is reachable from `start`.
- Every non-end node has at least one outgoing edge; end nodes have none.
- Every node id has a matching folder under `content/nodes/` when a body is
  required, and every folder has a matching node id.
- Node ids match `^[a-z0-9]+(-[a-z0-9]+)*$`.
- Titles and answer labels are non-empty.

`group` is an optional Cyrillic label used for the progress display. The
order of groups is the order of first appearance in the file.

Answer labels and titles are transliterated with everything else.

## Build and transliteration

- Tooling: Astro, Node 24 in `.nvmrc` and CI, `engines.node >=22.12.0`,
  npm with a committed lockfile. No UI framework. Zod validates the graph and
  front matter at build time.
- Routes: Cyrillic at the root, Latin under `/lat/`.
  - `/` and `/lat/` — home page with resume button.
  - `/step/<node-id>/` and `/lat/step/<node-id>/` — one page per node.
  - The script toggle links between the two versions of the current page.
- Transliteration runs at build time over titles, answer labels, UI
  strings, and rendered Markdown HTML. Direction is Cyrillic to Latin
  only. `translit-overrides.yaml` is applied first for words where the
  rule-based mapping is wrong (foreign names, digraph edge cases). URLs,
  image paths, and HTML attributes are left untouched.
- Images go through Astro's image pipeline: resized for phone widths,
  served as WebP with original as fallback. Authors drop in any size.
- The Latin mirror is produced by the content loader, not by
  post-processing HTML: each node's Markdown source is read twice, once
  raw and once transliterated, and both are rendered by Astro's Markdown
  pipeline. Transliteration touches only Cyrillic code points, so
  Markdown syntax, image paths, and URLs are untouched by construction.
- Output is static HTML/CSS/JS/images with the Pages base path baked in
  via Astro `site` and `base` config.

## Wizard runtime on the phone

- Progress storage: one local-storage key holding `{ current, path:
[{ node, answer }], updatedAt }`. Written on every node page load.
  Nothing leaves the device.
- Home page: if progress exists, the first element is a large "Наставите
  где сте стали" button linking to `current`; below it a smaller "Почните
  испочетка" that clears storage after a one-line confirmation.
- Back: browser back works because every node is a page. Each page also
  shows a large "Назад" button that goes to the previous node in the
  stored path. Without stored progress it falls back to history back.
- Progress display: group name and position among groups, for example
  "Регистрација · део 2 од 4". No linear step count, since the graph
  branches.
- Step with `external`: a large button opening the URL in a new tab, then
  the fixed instruction "Када завршите, вратите се овде", then the node's
  answers.
- Card nodes: full-screen layout, larger type, print stylesheet that hides
  navigation and prints body only. Script toggle visible so a clerk can
  read Latin if preferred.
- Home-screen install: web-app manifest (name, icons, `start_url` and
  `scope` equal to the Pages base path (`/egradjanin-korak-po-korak/`),
  generated at build from Astro config so a custom domain later needs no
  manual edit, `display: standalone`) plus `apple-touch-icon` for iPhone.
- Offline (stretch, done last): a hand-written `public/sw.js`, registered
  under the base path, caching visited pages and `/_astro/` assets. No
  PWA integration (the Astro one does not support Astro 7).
- Without JavaScript every page renders and every link works. Only the
  resume button, stored back path, and progress display are absent.

## Deploy and quality gates

- One GitHub Actions workflow:
  - On pull request: install, lint, test, build, Lighthouse CI.
  - On push to `main`: the same, then publish the build to GitHub Pages
    with the official `actions/upload-pages-artifact` and
    `actions/deploy-pages`.
- Pages source is set to "GitHub Actions" via the GitHub CLI.
- Lighthouse CI runs a mobile profile against the home page, one question,
  one step with `external`, and one card. Accessibility score below 90
  fails the check.
- Prettier with the Astro plugin, and `astro check` for TypeScript errors
  in `.astro` and `.ts` files. No ESLint in v1.

## Testing

- Graph validation (Vitest): dangling edge, unreachable node, missing body
  for step and card, non-end node without edges, end node with edges,
  folder/id mismatch, bad id format.
- Transliteration (Vitest): digraphs љ њ џ, uppercase and title case,
  overrides applied, Latin URLs and paths untouched inside mixed text.
- Progress storage (Vitest with a fake local storage): save, resume, back,
  reset, corrupted value ignored.
- Build as integration test: a sample graph containing every node type and
  the external-link and three-answer cases ships in the repo from day one,
  so the pipeline is exercised end to end before real content arrives. The
  sample is replaced when real content lands.
- Manual gate before the demo, recorded in CONTRIBUTING: open on a real
  Android and a real iPhone, add to home screen, complete one path,
  resume after closing the app, print a card.
- Built-output tests (Vitest, separate config, run after `astro build`):
  every node has a Cyrillic and a Latin page, `<html lang>` is correct, a
  Markdown image is served from `/_astro/`, the manifest `start_url`
  equals the base path.

## Contributing notes (to be written as CONTRIBUTING.md)

- How to add a node: create the folder, write `index.md`, add the node to
  `graph.yaml`, run `pnpm build`.
- How to run locally: `pnpm install`, `pnpm dev`.
- Where fixed UI labels live and that they are Cyrillic only.
- The manual phone checklist above.

## Out of scope for v1

- CMS or in-browser editing.
- Keeping screenshots current.
- Desktop layout.
- Analytics of any kind.
- Custom domain (supported by config, not set up).
